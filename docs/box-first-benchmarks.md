# Box-first vs MRI vs Frozone-Interpreter Benchmarks

Three-way wall-clock comparison across runtimes, generated by `rake bench_compare`.

## Workloads

The harness `run_benchmark(N) { ... }` records `ms/iter` but the iteration counts and per-iter sizes differ between the **stub** and **bench** files:

- **Stub workload** — `bench/stubs/<name>.rb` — sized for compiled performance (e.g. `fib(35)×3`). Used for the MRI and box-first columns.
- **Bench workload** — `bench/benchmarks/<name>.rb` — sized for the tree-walking interpreter (e.g. `fib(20)×3`). Used for the interpreter column.

Cells are **wall-clock total seconds** for the run, not normalised per-iter — directly comparable within a column, but the box-first/MRI columns use a much larger workload than the interpreter column.

`INTERP_BENCH_N=1` and a 5-min timeout are applied to the interpreter row by default. Some benchmarks (`sudoku.rb` does 20 hard puzzles per iteration) are still infeasible at the tree-walking level.

## Methodology

- **MRI**: stock CRuby (`ruby --version` → see footnote).
- **Box-first**: `FROZONE_CPP=1 FROZONE_BOX_FIRST=1 frozone.rb --aot <stub>` → `g++ -O2 -std=c++20` with Boehm GC + Onigmo.
- **Interpreter**: `frozone.rb <bench-file>` (default Prism parser, no flags).

No primitive-type specialisation in box-first yet (Integer/Float/etc. are uniformly boxed). TI + specialisation is the perf path; current numbers should be read as a **boxed-only baseline**.

### Reading the numbers

**Box-first vs MRI** — the two integer-arithmetic-heavy workloads (`fib`, `nqueens`) are 5–7× slower than MRI — exactly the territory we expect uniform boxing to hurt. Every `+`, `<`, `==` allocates an arg-Array, dispatches via vtable, returns a freshly-allocated Integer. After TI + Integer specialisation lands these should close substantially.

The two compute-heavy mixed-method workloads (`blurhash`, `sudoku`) already **beat** MRI by 2.5–6.6×. Both have rich method-dispatch surfaces where MRI's per-call overhead exceeds the cost of boxed C++ vtable dispatch. Worth a closer look later — could surface patterns to lean into.

**Interp vs MRI** — same workload, so the ratio is a clean slowdown factor. Tree-walking 25× slower than MRI on `fib`, 50× on `nqueens`. Anything heavier (real `blurhash`, `sudoku`'s 20 hard puzzles) doesn't fit in 5 minutes even at `BENCH_N=1`. The factor varies a lot with the workload's mix (more block dispatch / closures = more overhead).

### Caveats

- No primitive-type specialisation in box-first yet. All Integer/Float operations go through boxed virtual dispatch. **Read the box-first column as a pre-specialisation baseline.**
- Wall-clock totals only — no per-iteration normalisation, no warmup, no medians. Run-to-run variance can be 2–3× on shorter rows (sudoku box-first measured at 3.28s and 1.10s on consecutive runs). Use as a directional indicator, not a precision measurement.
- Box-first compile time is **not** included (regenerating + g++ on a 5MB cpp adds 1–2 minutes per benchmark). The `Box-first` column is binary execution time only.
- The same wall-clock is *not* directly comparable across the two halves of the table — different workloads. Keep MRI(stub) and MRI(bench) as separate baselines.

## Reading the numbers

Box-first vs MRI ratio ≈ "how much overhead does uniform boxing impose on this workload." Expect roughly 5–10× slower than MRI today on integer-heavy code (fib), less on allocation-heavy code where MRI's GC dominates. After TI + Integer/Float specialisation, expect the gap to close substantially on hot loops.

Box-first vs Interpreter ratio is roughly "what AOT compilation buys you over a tree-walker." Even unspecialised, AOT-compiled C++ should be at least 50× faster than the interpreter — closer to 1000× on tight loops once the workloads scale up.

## Footnotes

- Workload constants are baked into `bench/stubs/<name>.rb` (compiled-side) and `bench/benchmarks/<name>.rb` (interpreted-side). Edit there to retune.
- `BENCH_N` env var overrides per-run iteration count (the harness reads it inside `run_benchmark`).
- Box-first uses `cpp/gen/box/<name>.cpp` (regenerated each invocation) compiled to `cpp/gen/box/<name>_box`. Build flags include the Onigmo regex library and Boehm GC (`-lgc`).
